# v0.3.0

- 增加 @ 提及并设为新 Worker 的默认规则，名称可带或不带 @。
- 匹配打开 Issue 的标题、正文和评论；完整名称匹配，不将前缀、邮箱或路径当作点名。
- 每条评论独立去重，同一 Issue 的新点名评论可再次唤醒；通知仅带原文链接。
- GitHub 仓库从已登录账号可访问的列表选择，支持刷新，已有配置保留原规则。
- 监测、编辑和立即检查按钮放到各个 Worker 行，各自独立控制。
- 每个 Worker 显示下次检查倒计时，检查时显示“检查中”，停止后清空。
- 手工立即检查无需开启持续监测；查询新的匹配通知后即可唤醒，不改变定时计划。
- SQLite 版本 1 原地迁移到版本 2，保留历史和原去重记录。
- 修复退出时后台查询取消后的空结果回调错误。
- 开发约定：每轮修改前拉取 GitHub 最新代码，验证后自动提交、推送。

验证：81 项测试通过；界面截图已检查。真实验收使用已有测试 Issue #1 上两条临时评论和新建只读会话：各产生一条通知，agent 各自通过 gh 读取对应评论；空轮询和重复轮询均为 0 个 agent 回合，Dispatcher 模型调用为 0，测试评论已删除。见 mention-acceptance-result.json。

Windows EXE 的实际启动结果见 packaged-smoke-result.json。旧的 v0.2 通知报告保留为 Label 行为的历史验收。

限制：@ 规则是纯文本匹配，引用和代码块中的完整点名也会匹配。首次监测会匹配已有打开 Issue 中的历史提及，每条来源只自动通知一次；编辑已通知评论不会重发。SDK 无法抢占其他 Codex 进程的写入权，agent 仍使用既有模型额度和权限。
