# v0.2.0

改为简单的多 Worker 通知器：

- 主界面只有 Worker 表格、添加 / 编辑和同一个开始 / 停止监测按钮。
- GitHub / Codex 连接成功显示绿灯。
- 配置会话后自动读取项目目录和会话名称。
- 删除任务整理模型、目标模型覆盖、任务模板、Dry Run、实时输出面板。
- 只查 Issue 元数据；通知仅含固定指令和经过验证的 Issue 地址。
- 空轮询、重复 Issue 静默；去重记录可跨重启保留。
- SDK 收到回执即显示“已通知”，agent 自己读取、执行和收尾。
- 停止监测不打断 agent；后台保持运行时直到已通知回合结束。
- 保存配置只读验证，实际通知的 active writer 冲突有限重试。
- v0.1 数据兼容，旧模型与模板设置忽略。

验证：59 项测试通过。真实验收使用现有 Issue #1、#2 和独立新会话，两次通知后 agent 分别运行 gh 自行读取 Issue；空轮询与重复轮询均为 0 个 agent 回合，Dispatcher 模型调用为 0，GitHub 写入为 0。

Windows 打包和程序启动检查结果见 packaged-smoke-result.json。源代码、示例 UI 截图和报告在仓库同步。

已知限制：官方 SDK 不能抢占其他 Codex 进程的会话写入权。通知成功不代表 Issue 完成；agent 仍使用它自己的模型额度和既有权限。真实验收验证只读获取和同一会话通知，没有让 agent 修改业务项目或关闭测试 Issue。
